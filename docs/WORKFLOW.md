# Workflow

PitFlow의 실제 업무 흐름을 간단히 정리합니다.

## 전체 흐름

```text
고객 차량 등록
      ↓
정비 예약
      ↓
관리자 예약 확인
      ↓
차량 입고
      ↓
정비사 배정
      ↓
정비 작업
      ↓
부품 사용 / 반환
      ↓
정비 완료
      ↓
관리자 정산
      ↓
결제
      ↓
관리자 차량 출고
      ↓
고객 정비 이력
```

## 예약

고객이 차량과 정비 서비스를 선택합니다.

예약 시간 충돌 여부는 서버와 Database가 최종 확인합니다.

예약 당시의 서비스 이름과 가격은 이후 서비스 정보가 변경되어도 유지됩니다.

## 입고

관리자가 실제 방문 차량을 입고 처리합니다.

주행거리를 기록하고 정비 작업을 생성한 뒤 정비사를 배정합니다.

## 정비

정비사는 자신에게 배정된 작업만 처리합니다.

실제로 사용한 부품만 재고에서 차감하고 반환한 부품은 다시 재고에 반영합니다.

부품이 부족하면 관리자에게 신고할 수 있습니다.

관리자가 부족 신고를 확인하고 해결하면 현재 담당 정비사에게 해결 알림이 전달됩니다.

## 정비 완료

정비사는 작업 완료까지만 담당합니다.

결제와 차량 출고는 관리자가 처리합니다.

## 정산과 결제

관리자는 완료된 작업을 기준으로 정산 명세를 발행합니다.

고객은 정비 이력 화면에서 Toss 테스트 결제를 할 수 있습니다.

관리자는 Toss 또는 현금·카드·계좌이체로 수납할 수 있습니다.

환불이나 수납 취소가 발생하면 남은 결제 금액이 다시 복원됩니다.

## 출고

남은 결제 금액이 있으면 차량을 출고할 수 없습니다.

전액 결제된 뒤 관리자가 실제 차량 인도를 확인하고 출고 처리합니다.

## 재고

```text
입고 → 증가
사용 → 감소
반환 → 증가
재고 수정 → 실제 확인 수량 반영
```

부품 부족 신고나 작업 취소만으로 재고를 자동 변경하지 않습니다.
