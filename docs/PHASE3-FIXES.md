# 3단계 추가 수정 — 재고 편집·예약 안내·기본 목록

기준: 3단계 커밋 `7b72d8b` 위에 적용하는 추가 패치입니다. 브랜치는 `feat/work-orders`이며 main과 README를 변경하지 않습니다.

## 재고·부품 관리

- **이름·단가 등 부품 정보 수정** 메뉴를 기본으로 펼칩니다. 과거 이동 이력의 이름·단가는 바뀌지 않습니다.
- **재고 수정 · 실사 보정**은 추가할 수량이 아닌 실제 총 보유 수량을 받습니다. 0과 소수 셋째 자리까지 지원합니다.
- 관리자 권한, CSRF, Idempotency-Key가 필요합니다. 행 잠금 아래 조회 당시 expectedQuantity를 비교하고 실제 수량과의 차이를 ADJUST_IN/ADJUST_OUT 이력으로 기록합니다.
- 다른 요청이 재고를 바꿨으면 409로 거절합니다. 새로고침 후 실사 수량을 재확인합니다. 중복 키는 원래 결과를 재전송하며 잔량·이력·요청 키는 함께 커밋/롤백됩니다.
- 재고가 0인 부품은 **삭제**할 수 있습니다. 실제 행을 삭제하지 않고 목록에서 숨기며 과거 이력과 정비 항목 연결을 보존합니다.
- **삭제한 부품도 표시**를 켜면 조회·복원할 수 있습니다. 복원은 비활성 상태이므로 정보 수정에서 사용 가능 여부를 설정합니다.
- 삭제한 부품의 과거 사용 건에서 실제 반환이 발생하면 목록에 비활성 상태로 복원합니다. 회수한 재고가 숨겨지지 않도록 합니다.
- 같은 부품번호를 새 부품으로 재사용하는 대신 기존 부품을 복원합니다. 삭제·복원 사유는 part_events에 남습니다.

## 예약 입고

기존 화면은 VISITED만 표시하여 내일의 대기/확정 예약이 보이지 않았습니다. 선택 날짜의 전체 예약과 상태, 이미 입고한 예약, 입고 가능한 건수를 표시하도록 수정했습니다.

1. 날짜별 예약에서 **예약 확정**.
2. 실제 차량이 방문하면 **방문 처리**.
3. 방문 처리된 미입고 예약을 선택하여 주행거리·담당자를 입력하고 **입고 등록**.

후속 휴무·조기 입고 수정에서 30분 전 제한을 해제했습니다. 확정 예약은 예약일 전에도 방문 처리할 수 있으며 종료 전 제한은 유지합니다. 버튼은 서버 allowedStatuses에 따라 표시하며 빈 목록에는 이유와 캘린더 링크를 제공합니다. 시간이 도래하면 새로고침합니다.

## 정비·부품 기본 목록

기본 정비 18종: 엔진오일, 타이어, 배터리, 엔진 에어필터, 에어컨 필터, 앞/뒤 브레이크 패드, 브레이크액, 냉각수, 점화플러그, 와이퍼, 변속기 오일, 보조 구동벨트, 전구, 워셔액, 타이어 위치 교환, 휠 얼라인먼트, 차량 기본 점검.

관련 부품 17종을 제공합니다. **새 부품의 재고·단가는 모두 0**입니다. 기존과 같은 이름·단위의 부품 또는 같은 기본 부품번호가 있으면 해당 부품을 연결하고 재고·단가·이름·활성 상태를 덮어쓰지 않습니다. 기존 정비 항목의 수정 내용도 보존합니다. 기본 공임은 시연 예시이며 실제 견적이 아닙니다.

service_part_requirements로 정비 항목과 부품 종류를 연결합니다. 관리자 부품 화면에 연결 정비를, 작업 상세에 준비 부품과 재고를 표시합니다. 사용 입력에서는 연결 부품을 먼저 표시하지만 **자동 차감하거나 사용 수량을 추정하지 않습니다**. 규격과 실제 사용량은 차종에 맞게 확인합니다. 사용자 추가 정비 항목의 연결 편집 UI는 후속 범위입니다.

## 마이그레이션·API

이미 적용된 V1/V2/V3는 변경하지 않습니다. 새 Java Flyway migration `V4__inventory_adjustments_and_catalog`을 추가합니다. V3의 자동 생성 CHECK 이름이 PostgreSQL/H2에서 다르므로 메타데이터에서 종류 관련 CHECK 두 개만 찾아 확장합니다. 기존 잔량·원장 행은 재작성하지 않습니다. 기본 목록 추가도 V4에서 한 번만 실행하므로 재시작할 때 사용자 데이터가 초기화되지 않습니다.

| API | 내용 |
|---|---|
| POST /api/admin/parts/{id}/adjustments | quantity, expectedQuantity, reason |
| PATCH /api/admin/parts/{id} | 기존 이름·정보 수정 API 유지 |
| DELETE /api/admin/parts/{id} | reason, 재고 0일 때 목록 삭제 |
| POST /api/admin/parts/{id}/restore | reason, 비활성으로 복원 |
| GET /api/admin/parts?includeArchived=true | 삭제 포함 조회 |
| GET /api/admin/parts | 삭제 제외, services 연결 목록 포함 |
| GET /api/admin/work-orders/{id} | suggested_parts 포함 |

## Windows 적용

이전 `pitflow-phase3.patch`를 적용한 상태에서 추가 패치만 적용합니다. 각 명령이 성공했는지 확인하고 다음 명령을 실행합니다.

```powershell
cd "$env:USERPROFILE\Desktop\pitflow"
git switch feat/work-orders
git status --short
git am "$env:USERPROFILE\Downloads\pitflow-phase3-fixes.patch"
docker compose up --build -d
docker compose logs --tail=100 backend
```

DB 볼륨을 삭제하지 않습니다. 백엔드 로그에서 V4 적용을 확인한 뒤 다시 로그인하여 관리자 부품/정비 작업 화면을 확인합니다. 기존 예약·재고는 유지됩니다.

확인이 끝나면 두 단계의 커밋을 함께 올립니다.

```powershell
git push -u origin feat/work-orders
```
