# 2단계 — 정비 예약

## 현재 브랜치 적용 (VSCode PowerShell)

GitHub 브랜치가 업로드된 뒤 아래 명령으로 적용합니다. 기존 작업 변경사항은 먼저 커밋해 주세요.

```powershell
cd "$env:USERPROFILE\Desktop\pitflow"
git fetch origin
git switch feat/appointments
git pull --ff-only origin feat/appointments
docker compose up --build -d
docker compose ps
docker compose logs --tail=100 backend
```

처음 가져오는 경우 `git switch feat/appointments`가 원격 브랜치를 자동 추적합니다. 이미 같은 이름의 로컬 브랜치가 있으면 이동 후 fast-forward로 갱신합니다. 브랜치가 갈라져 pull이 실패하면 해당 오류를 확인하여 해결해야 합니다.

V1은 유지하고 V2만 추가합니다. 기존 회원·차량·정비 항목 데이터는 보존되며, DB 볼륨 초기화가 필요하지 않습니다. 컨테이너 재시작 후에는 다시 로그인하세요.

## 고객 시연

1. http://localhost:3000 에서 로그인합니다.
2. `내 정비 예약` → `정비 예약하기`를 선택합니다.
3. 차량과 정비 항목을 하나 이상 선택합니다. 여러 항목의 시간이 합산됩니다.
4. 운영일과 방문 시각을 선택한 후 신청합니다. 상태는 `확인 대기`입니다.
5. 관리자 확인 후 `예약 확정`이 표시됩니다. 내역은 월별로 조회합니다.
6. 시작 전 예약을 취소하면 같은 시간에 다시 예약할 수 있습니다.

## 관리자 시연

1. 로그아웃 후 `.env`의 기존 관리자 계정으로 로그인합니다.
2. `예약 캘린더`에서 예약 날짜를 선택합니다.
3. 작업 공간별 시간표의 예약을 선택하고 고객·차량·요청사항을 확인합니다.
4. `예약 확정`을 선택합니다. 확정한 예약은 예약일 전에도 방문 처리할 수 있으며, 예약 종료 전까지 가능합니다.
5. 미방문 처리는 예정 종료 이후, 취소는 대기·확정 상태에서 가능합니다.

이메일·문자 알림은 이번 단계에 포함하지 않습니다. 고객은 화면을 새로고침하여 변경 상태를 확인합니다.

## 동시성 검증

`PhaseTwoIntegrationTest`는 별도 스레드의 두 HTTP 요청을 동시에 실행합니다. 서로 다른 고객이 같은 공간의 90분 예약을 요청하면 201 한 건·409 한 건, 예약 1건·항목 2개·슬롯 3개가 남는지 검사합니다. 후반 슬롯만 겹칠 때 앞서 저장된 슬롯과 예약 항목도 모두 롤백되는지 별도로 검증합니다. 확정·취소 경쟁 시 최종 취소 상태와 슬롯 0개도 검사합니다.

추가로 동일 차량의 서로 다른 공간 중복, 연속 슬롯 가용성, 가격 스냅샷, 차량 삭제 제한, 타인 데이터 접근, CSRF, 관리자 권한, 휴무일·과거·종료시간·오프셋을 검사합니다.

```powershell
cd "$env:USERPROFILE\Desktop\pitflow\backend"
.\mvnw.cmd test
cd ..\frontend
npm ci
npm run build
npm run typecheck
```

로컬 기본 테스트 DB는 H2 PostgreSQL 모드입니다. GitHub Actions는 실제 PostgreSQL 17로 같은 테스트를 실행합니다. 실제 DB 테스트는 서비스용 DB와 분리된 빈 테스트 DB에만 연결하세요.
